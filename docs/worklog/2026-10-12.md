## 3. Android 앱 실기동 검증

### 실행 환경 구성
- Android SDK에 에뮬레이터와 `system-images;android-34;google_apis;x86_64`를 설치하고, AVD `ringdog_api34`(Pixel 6)를 만들었습니다.
- 로컬 backend: WSL `docker compose`(postgres, kafka, opensearch) + Windows에서 `backend-api`(:4000), `order-consumer`(:4002) 실행.
  에뮬레이터는 `10.0.2.2:4000`으로 접속합니다.

### 에뮬레이터 이슈와 해결
| 증상 | 원인 | 해결 |
|---|---|---|
| `sdkmanager`가 `Package android-34 not found` | cmd가 패키지 경로의 `;`를 인자 구분자로 자름 | 패키지명을 따옴표로 감쌈: `'"system-images;android-34;google_apis;x86_64"'` |
| 콘솔 창을 닫으면 에뮬레이터도 종료 | `Start-Process`가 콘솔 창을 같이 띄움 | `-WindowStyle Hidden`으로 실행 |
| "Could not automatically detect an ADB binary" | `ANDROID_SDK_ROOT`가 없는 상태로 실행 | 실행 전에 `ANDROID_SDK_ROOT`/`ANDROID_HOME` 설정 (기능 영향 없는 경고) |
| "Process system isn't responding" 반복 | 메모리 2GB 부족 + 첫 부팅 때 GMS/YouTube/Gmail 초기화 부하 (load 15, 스왑 사용) | AVD 메모리 3GB, 호스트 Gradle 데몬 정리(여유 1GB → 5GB), YouTube·Gmail 비활성화, 애니메이션 끔 |
| `-gpu host`에서 부팅 중 종료 | Intel Iris Xe 호스트 GPU 렌더링 실패 | `swiftshader_indirect`(소프트웨어 렌더링) 유지 |

## 4. Android RUM 세션이 안 들어오던 문제

**증상:** 앱을 사용해도 Datadog RUM에 세션이 없었습니다.

**구간별 확인:**
| 구간 | 결과 | 근거 |
|---|---|---|
| APK에 키 포함 | 정상 | 생성된 BuildConfig에 application ID와 client token이 따옴표 없이 들어 있음 |
| SDK 초기화와 수집 | 정상 | 앱 캐시 `datadog-*/rum-v2/`에 배치 파일 26개가 쌓여 있음 |
| 업로드 | **실패** | 이 네트워크에서 Datadog intake 인증서 발급자가 `Zscaler Intermediate Root CA`로 나옴. 에뮬레이터는 Zscaler CA를 신뢰하지 않아 TLS 검증 실패 |

**해결:**
- `local` flavor에 `network_security_config.xml` 추가: `debug-overrides`에서 사용자 CA를 신뢰합니다.
  - 디버그 빌드에만 적용되고, 릴리스 빌드와 `demo` flavor에는 영향이 없습니다.
  - config를 지정하면 `android:usesCleartextTraffic`이 무시되므로, cleartext 허용도 config로 옮겼습니다.
- 에뮬레이터에 Zscaler 루트 CA를 사용자 CA로 설치했습니다 (절차: `apps/android-app/README.md`). CA 파일은 repo에 넣지 않았습니다.
- 결과: 다시 설치하자 쌓여 있던 배치가 26개에서 0개로 업로드됐고, Datadog에서 세션 3개를 확인했습니다.

**부수 수정 (`local.properties`):**
- Datadog 온보딩 화면의 변수명(`rum.applicationId = "..."`)으로 값을 넣어도 동작하도록 빌드 스크립트를 바꿨습니다.
  - `DD_RUM_*`와 `rum.*` 키를 모두 읽습니다.
  - 값을 감싼 따옴표를 떼고, `<PLACEHOLDER>` 형태의 값은 무시합니다.
- `variant`는 `BuildConfig.FLAVOR`로 설정합니다 (샘플 코드의 `appVariantName` 자리).
- `env`는 `rum.environmentName`이 있으면 그 값, 없으면 flavor에 따라 `local`/`demo`입니다.

## 5~6. 트레이스 샘플링 100%와 Session Replay

- `NetworkModule`: `DatadogInterceptor.Builder(...).setTraceSampleRate(100f)`.
  기본값 20%일 때는 리소스 16개 중 6개에만 `trace_id`가 붙었습니다.
- Compose용 Session Replay 확장은 SDK 2.16.0부터 있습니다. 그래서 Datadog SDK 전체를 **3.15.0**으로 올렸습니다.
  - 기존 Datadog 연동 코드는 수정 없이 컴파일됐습니다.
  - 하위 라이브러리(androidx core 1.15 등) 요구로 `compileSdk` 34→35, AGP 8.5.2→8.7.3으로 올렸습니다.
    `targetSdk`는 34 그대로입니다.
  - 덤으로 `setRemoteConfigurationId`가 생겨 `local.properties`의 `rum.remoteConfigId`를 적용했습니다.
- Session Replay 설정: 녹화 비율 100%, `ComposeExtensionSupport`, `TextAndInputPrivacy.MASK_SENSITIVE_INPUTS`
  (비밀번호 같은 민감 입력만 가리고 상품명·가격은 보임).
- 검증: 단위 테스트 49/49 통과, 기기에서 `session-replay-v2` 대기열이 업로드됨(남은 파일 0).
  Datadog UI의 Replay 탭에서 재생되는지는 아직 확인하지 못했습니다 (MCP 조회가 시간 초과).
- 빌드 중 `Could not move temporary workspace` 오류: Cursor의 Java 언어 서버가 Gradle 동기화를 동시에 돌린 것으로 보임.
  `--no-parallel`로 다시 빌드하니 해결됐습니다.

## 확인한 사실 (Q&A)

- **노드 2대 안의 서비스 배치:**
  - DaemonSet(`datadog-agent`, `aws-node`, `kube-proxy`)은 노드마다 1개씩 돕니다.
  - 앱 Pod 4개(각 replica 1)와 클러스터 단위 Pod는 `nodeSelector`, `affinity`, `requests`가 없어서 스케줄러가 임의로 배치합니다.
  - 앱의 `DD_AGENT_HOST`가 `status.hostIP`라서, 각 앱은 자기가 떠 있는 노드의 Agent로 트레이스를 보냅니다.
  - replica 1개라 HA 구성은 아닙니다.
- **Kafka 위치:** EKS 밖의 Amazon MSK입니다. Private Subnet 2a·2c에 브로커가 1대씩 있고, EKS 클러스터 보안 그룹에서 오는 9092/9094만 허용합니다.
- **DSM Kafka Console:**
  - Kafka Consumer 클러스터 체크는 `backend-api` Service 어노테이션에 적용돼 있습니다 (`enable_cluster_monitoring: true`).
  - **`enable_kafka_console: true`는 없습니다.** 또 Agent 7.84.0 이상이 필요한데, Agent 버전은 고정돼 있지 않습니다.
