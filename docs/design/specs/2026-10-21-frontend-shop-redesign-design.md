# 프론트엔드 쇼핑몰형 디자인 개편 설계

- 작성: 2026-10-21
- 대상: `apps/frontend` (Next.js App Router, Tailwind)
- 시안: `.superpowers/brainstorm/709-1792562883/content/` — `home-direction.html`(A안 선택), `detail-page-v2.html`(상세 확정안)

## 1. 왜 하는가

RingDog는 Datadog 관측 데모용 쇼핑몰이다. 지금 화면은 귀여운 단일 그리드에 상품 이미지 대신 태그 아이콘을 그려 넣은 형태라, 시연에서 청중이 처음 보는 순간 "데모용 샘플 앱"으로 읽힌다.
사용자가 원하는 것은 두 가지다.

1. **첫인상**: 화면을 띄우자마자 "진짜 쇼핑몰이네"로 보일 것.
2. **시연 중에도 진짜 같을 것**: 장애를 보여 주는 동안(인기상품 지연, 결제 실패) 실제 쇼핑몰에서 사고가 난 것처럼 몰입되어야 한다.

참고 대상은 쿠팡·무신사처럼 배너와 카테고리가 있는 국내 쇼핑몰이고, 두 방향 시안 중 **A안(쿠팡형: 밝고 정보가 촘촘한 마켓)**으로 정했다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 홈: 쿠팡형 헤더(큰 검색창) + 카테고리 줄 + 자동으로 넘어가는 배너 + 원형 카테고리 아이콘 + "지금 많이 팔리는 상품"(기존 인기상품 위젯) + 전체 상품 그리드.
- 상품 상세: 쿠팡형 상세 레이아웃(아래 4.3).
- 장바구니·주문내역·로그인·회원가입·에러 페이지도 같은 톤으로 맞춘다(사용자 결정).
- 상품마다 실제 키링 사진을 보여 준다.

**비목표**
- 백엔드 API, DB 스키마, 시드 데이터는 바꾸지 않는다(내 판단 — 시연 튜닝 값과 시드 시간이 이미 맞춰져 있음). 화면에 필요한 값이 API에 없으면 프론트에서 만든다(4.5).
- 실제 리뷰 작성, 찜, 쿠폰함, 정렬·필터 서버 기능 같은 새 기능은 만들지 않는다.
- 모바일 전용 레이아웃 최적화는 하지 않는다. 다만 좁은 화면에서 깨지지 않을 정도의 반응형은 유지한다.

**실패 조건(동작해도 실패로 본다)**
- 시나리오 ① 시연 흐름이 깨지는 것(3장 제약 위반). k6 브라우저 트래픽이 장바구니 담기·결제를 못 하거나, RUM 액션 이름이 바뀌어 대본의 Rage Click 장면이 사라지는 것.
- 눌리는 것처럼 보이는데 아무 동작도 하지 않는 요소. RUM이 이것을 **dead click**으로 잡아 시연 중 프런트 오류 신호가 섞인다. 장식 요소는 클릭 가능해 보이지 않게 하거나, 실제로 동작하게 만든다.
- 남의 쇼핑몰 로고·이미지·상표를 가져다 쓰는 것. 저장소가 public이다.

## 3. 반드시 지킬 제약 (시연 의존)

`deploy/helm/charts/ringdog/files/traffic/browser.js`(k6 브라우저)와 RUM 대본이 아래에 기대고 있다.

1. **홈에서 처음 나오는 `장바구니` 버튼**: k6는 `(//button[normalize-space()="장바구니"])[1]`을 누른다.
   - 문서 순서상 처음 나오는, 텍스트가 정확히 `장바구니`인 `<button>`은 **상품 카드의 장바구니 담기 버튼**이어야 한다.
   - 헤더의 장바구니는 지금처럼 **링크(`<a>`)**로 둔다. 배너나 카테고리에 같은 텍스트의 버튼을 두지 않는다.
   - 로그인한 사용자가 이 버튼을 누르면 지금처럼 즉시 담겨야 한다. 확인 모달 같은 추가 단계를 넣지 않는다.
2. **장바구니 결제 폼**: k6는 `main form:has(input[placeholder="RINGDOG100"]) button[type="submit"]`을 누른다.
   - 결제 폼은 `<main>` 안에 있어야 한다.
   - 쿠폰 입력의 placeholder는 `RINGDOG100`, 결제 버튼은 그 폼의 `type="submit"`을 유지한다.
3. **RUM 액션 이름은 버튼 텍스트에서 자동으로 정해진다.**
   - `장바구니`, `결제하기`, `결제 처리 중...` 문구를 그대로 둔다.
   - 결제 중에도 결제 버튼은 **enabled**를 유지하고, 재진입은 `useRef` 가드로 막는다. 그래야 Rage Click이 발생한다(현재 구현 유지).
4. **인기상품 위젯**(`TrendingWidget`, `lib/carousel.ts`, `ac901a7`)
   - 동작은 유지한다: 기능 플래그 OFF면 숨김, [<][>] 넘김, 로딩 스켈레톤.
   - 모양만 새 카드 톤에 맞춘다.
   - 장애 중 이 위젯이 느리게 뜨는 것 자체가 시연 장면이므로, 로딩 상태가 눈에 보여야 한다.
5. **RUM 초기화 순서**(`RumInit`, `1d58bea`)와 프로파일링 헤더는 건드리지 않는다.
6. 기존 테스트(`carousel.test.ts`, `trending.test.ts`, `datadogRum.test.ts`)는 계속 통과해야 한다.
7. 챗봇 위젯(`ChatWidget`)은 유지한다. 위치·톤만 맞춘다.
8. **시나리오 ②(잘못된 배포)의 쿠폰 동작**
   - 장바구니 쿠폰 입력칸은 지금처럼 `RINGDOG100`이 **미리 채워진 상태**로 시작한다(`docs/design/specs/2026-10-13-demo-bad-deploy-design.md`). 시연자가 비우고 주문하면 에러가 재현되어야 하고, k6 `COUPON_RATIO`는 `coupon.fill("")`만 한다.
   - 쿠팡식 "[쿠폰 적용]" 버튼은 두지 않는다. 결제 폼 안의 submit 버튼은 `결제하기` 하나뿐이어야 k6 선택자가 하나만 잡힌다.
9. **RUM 퍼널 경로**: `/`, `/products/[id]`, `/cart`, `/orders`의 URL 구조는 바꾸지 않는다.
10. **인기상품 위젯 카드에는 `장바구니` 버튼을 두지 않는다**(내 판단). 위젯이 그리드 위에 있어서 버튼이 생기면 k6가 누르는 상품이 "인기 1위"로 바뀐다. 그러면 주문 분포와 인기상품 결과가 시연 튜닝과 달라진다. 위젯 카드는 사진·이름·가격·순위만 보여 주고, 누르면 상세로 간다.
11. **새 화면이 인기상품 API(`/api/products/trending`)를 추가로 부르지 않는다.** 장애 대상 쿼리라 호출이 늘면 시나리오 ①의 p95와 모니터 값이 흔들린다. 지금처럼 홈 위젯 한 곳에서만 호출한다.

## 4. 화면별 설계

### 4.1 공통

- **색**: 기존 `primary` 팔레트(#FF6A4D 계열)를 쿠팡형 강조색으로 그대로 쓴다. 배경은 흰색. 회색 구분선이 많은 촘촘한 톤으로 간다.
- **글씨**: 시안 v2 기준으로 지금보다 2~4px 크게 잡는다(사용자 결정). 본문 14~15px 이상, 상품명 22px, 판매가 26px.
  - 귀여운 제목 폰트 `Jua`는 빼고 `Noto Sans KR` 하나로 통일한다(내 판단 — 쿠팡형 톤에 맞춤).
- **사진 영역**: 시안 v1보다 작게 잡는다(사용자 결정). 상세에서는 사진 열이 정보 열보다 좁다. 홈 그리드도 같은 원칙으로 사진을 키우기보다 카드 수를 늘린다.
- **헤더**(모든 페이지)
  - 1줄: 로고(RingDog) / 강조색 테두리의 큰 검색창 / 장바구니·주문내역 링크, 로그인 상태에 따라 로그인·회원가입 또는 로그아웃.
  - 2줄: "☰ 카테고리"(누르면 카테고리 목록이 펼쳐짐) + 바로가기. 바로가기는 모두 실제로 이동하는 링크다(내 판단).
    - 타임세일 → `/?q=세일`: 대량 시드 "세일 키링" 1,140개가 나온다.
    - 신상품 → 홈의 전체 상품(최신순) 위치.
    - 그 뒤에 주요 카테고리 몇 개(동물, 우주 등) → 4.2의 카테고리 목록.
    - "베스트"나 "오늘의 특가"처럼 인기상품 API가 필요하거나 대상이 없는 바로가기는 두지 않는다(3장 11번).
  - 기존 검색(`/?q=`) 동작은 유지한다.

### 4.2 홈 (`/`)

위에서부터 순서대로 놓는다.

1. **배너**: 3장이 몇 초 간격으로 자동으로 넘어간다. 점 표시나 화살표로 직접 넘길 수도 있다. 문구 예: "타임세일 최대 50% ⚡", "신상 키링 입고", "전 상품 무료배송". 각 배너는 실제로 이동하는 링크다(검색 결과나 카테고리).
2. **원형 카테고리 아이콘 줄**: 기존 상품의 "모양" 태그 15종을 묶은 카테고리다. 누르면 해당 상품 목록으로 이동한다.
   - 묶는 방식은 내 판단이다. 예: 동물(고양이·강아지·곰돌이), 탈것(자동차·자전거), 우주(로켓·우주비행사·별·지구본), 일상(커피컵·책·카메라), 테크(에어팟), 스포츠(축구공), 꽃.
   - 목록은 기존 검색 API(`/api/products/search?q=`)로 가져온다. 여러 모양을 묶은 카테고리가 검색 한 번으로 제대로 나오는지는 builder가 확인한다. 안 되면 카테고리를 모양 단위로 나눈다.
3. **지금 많이 팔리는 상품**: 기존 `TrendingWidget`을 새 카드 모양으로 바꾼다(3장 4번 제약).
4. **전체 상품**: 기존 목록 API(최신순)를 쓴다. 지금처럼 처음 24개를 보여 주고, 아래에 실제로 다음 페이지를 이어 붙이는 **"더보기" 버튼**을 둔다(내 판단). 숫자 페이지 넘김은 만들지 않는다. 검색 결과도 같은 방식이다.
   - 카드 구성: 사진, 상품명, 할인율 + 판매가(+ 정가 취소선), 별점과 상품평 수, 배송 배지(무료배송/내일 도착), **`장바구니` 버튼**.
   - 정렬 탭(추천순, 낮은가격순 등)은 API가 최신순만 지원하므로 **두지 않는다**. 동작하지 않는 탭은 dead click이 되기 때문이다.
- 검색어(`?q=`)나 카테고리가 있으면 배너·아이콘·인기상품을 숨기고 "'고양이' 검색 결과 N개" 제목과 결과 그리드만 보여 준다(지금처럼 검색 시 위젯 숨김 유지).

### 4.3 상품 상세 (`/products/[id]`)

시안 `detail-page-v2.html` 기준이다.

- **카테고리 경로**: 홈 › 카테고리 › 모양. 각 단계는 링크다.
- **왼쪽**: 썸네일 세로 줄 + 대표 사진. 썸네일을 누르면 대표 사진이 바뀐다.
  - 상품당 실제 사진이 1장이면 같은 모양 사진 풀에서 최대 4장을 고른다(내 판단).
- **오른쪽 정보**
  - 상품명, 별점 + 상품평 수(누르면 리뷰 탭으로 스크롤).
  - 할인율, 정가 취소선, 판매가. 타임세일 표시.
  - 배송·소재·재고 표. 재고는 실제 `stock` 값을 쓴다.
  - 수량 선택(−/＋): 장바구니 API가 `quantity`를 받는다.
  - [장바구니 담기][바로구매]. 바로구매는 담은 뒤 `/cart`로 이동한다.
  - 상세 페이지 버튼 문구는 지금의 "장바구니에 담기"에서 "장바구니 담기"로 바뀌어도 된다. 시연이 기대는 것은 홈의 `장바구니`뿐이다.
- **아래**
  - 탭: 상품상세 / 상품평(N) / 배송·교환·반품. 같은 페이지 안의 섹션으로 스크롤한다.
  - 상품상세: 설명 문구와 사진.
  - 상품평: 가짜 리뷰 몇 개(4.5).
  - 배송·교환·반품: 고정 안내 문구.
  - "이 상품과 비슷한 상품": 같은 모양 키워드로 검색 API를 호출해 최대 5개.

### 4.4 장바구니·주문내역·로그인·회원가입·에러

- **장바구니**: 쿠팡형 2단 구성. 왼쪽은 담은 상품 목록(사진, 이름, 수량, 금액, 삭제), 오른쪽은 결제 금액 요약 박스와 쿠폰 입력, `결제하기`. **3장 2·3번 제약을 그대로 지킨다.**
- **주문내역**: 주문 카드 목록(주문일, 상태 배지, 상품 사진 썸네일, 금액, 취소 버튼 — 기존 기능 유지).
- **로그인·회원가입**: 가운데 정렬 폼 카드, 쿠팡형 입력창과 버튼. 기존 동작은 유지한다.
- **에러 페이지**: 같은 헤더와 톤.

### 4.5 화면용 가짜 값 (API에 없는 것)

할인율, 정가, 별점, 상품평 수, 배송 배지, 리뷰 문구는 DB에 없다. **상품 id를 시드로 한 결정적 함수**로 프론트에서 만든다(내 판단). 새로고침해도 같은 상품은 같은 값이 나오고, 서버 변경은 없다.

- **할인율**: 0%(일부 상품) 또는 5~50% 중 하나. 정가 = 판매가 / (1 − 할인율)을 100원 단위로 반올림.
  - 시나리오의 세일가 배치가 실제 가격을 바꾸면 판매가가 내려가 보이는 것이 자연스럽다. 정가는 "판매가에서 역산한 값"이라 세일 전후로 달라져도 문제없다.
- **별점**: 4.0~5.0. **상품평 수**: 10~500.
- **배송 배지**: "무료배송" 또는 "내일 도착".
- **리뷰**: 문구 템플릿 10여 개에서 상품별로 3개. 작성자는 마스킹된 가짜 아이디(`ring***`), 날짜는 최근 30일.
- 이 값들은 한 모듈(예: `lib/displayMeta.ts`)에 모으고 단위 테스트를 둔다. 같은 id면 같은 값, 범위 준수.

사용자는 이미지를 "알아서" 구해 넣기를 원했다. 방법은 내 판단이다.

- **출처**: 상업적 이용이 허용되고 출처 표기 의무가 없는 무료 사진(Unsplash License, Pexels License)만 쓴다. 실제 쇼핑몰이나 브랜드 상품 사진은 쓰지 않는다.
- **분량**: 모양 15종마다 1~3장, 배너용 3장, 카테고리 아이콘용 몇 장. 키링 실물 사진이 없는 모양은 그 모양의 소품 사진으로 대신한다.
- **저장**: `apps/frontend/public/images/` 아래에 저장소와 함께 커밋한다. 외부 핫링크는 쓰지 않는다(시연 중 외부 의존과 RUM 리소스 에러 방지).
  - 한 장당 대략 100KB 이하의 WebP 또는 JPEG로 줄인다.
  - `public/images/CREDITS.md`에 파일별 원본 URL과 라이선스를 적는다.
- **상품과 사진 연결**: 프론트에서 태그로 정한다. `imageUrl`이 있으면 그것을 쓰고, 없으면 상품의 모양 태그로 사진 풀을 찾는다.
  - 대량 시드 상품 1,140개("세일 키링 #N")는 모두 태그가 `미니, 별`이라 전부 같은 사진이 될 수 있다. 이 경우 id 해시로 전체 사진 풀에서 고른다. 그리드에 같은 사진이 줄줄이 나오지 않게 하기 위해서다.
  - DB의 `imageUrl`은 건드리지 않는다.
- **다운로드 환경**: 이 작업 PC는 회사 SSL 검사 때문에 Node fetch에 `NODE_OPTIONS=--use-system-ca`, WSL의 curl/wget에 `SSL_CERT_FILE=~/certs/ca-bundle.pem`이 필요할 수 있다.

## 5. 확인 방법

1. `pnpm --filter @ringdog/frontend` lint·타입체크·테스트·빌드 통과(기존 + 새 단위 테스트).
2. 로컬 또는 배포 환경에서 화면 확인: 홈·상세·장바구니·주문내역·로그인·회원가입. 사용자가 직접 보고 승인한다.
3. **시연 경로 확인**(배포 후, 데모 환경이 떠 있을 때)
   - k6 traffic-browser 로그에 에러가 없을 것.
   - Datadog RUM에서 HeadlessChrome 세션의 `장바구니`·`결제하기` 액션이 계속 들어올 것.
   - `inject` 중 결제 버튼 rage click이 잡힐 것.
   - 홈에서 dead click이 새로 늘지 않을 것.
4. 배포는 main push → cd. 데모 환경 일정에 맞춘다(환경이 내려가 있으면 다음 demo-up 때 확인).
